## Sari-Sari Store Inventory System

### 1. Encapsulation
it can be used by compiling these variables/categories into a single unit, an example is adding the name of the products into an array named "name_of_product". It can also be used for other categories such as the prices, item no., and etc. this can improve the organization of the objects by reducing the amount of variables used, as too many variables can be harder for it to debug and read, and cause for it to be more time consuming.

### 2. Abstraction
It can be used to form a generalized idea of the program or create a main goal. An example is using these sub problems such as storing the prices and product name to create a broader goal like making the vending machine more convinient and faster. This pillar can set the stage on the program, it is the base meaning that if you don't have a general idea of the matter you won't know what to do on your next step.

### 3. Inheritance
It allows the child class to inherit the attributes of the parent class, this promotes code reusability and it helps on making it easier and shorter. it can be applied to the sari-sari store by using the parent code as a product parent that stores the names, prices, and quantity of the products, while the chld class can act as a sub category that stores items such as "canned_foods" or "dessert_items" with specialized info like expiration dates but also still using the parent class as a basis. This can help on making it more organized and more clean, it can also help with code readibility and debugging by creating sub areas.

### 4. Polymorphism
It can be defined as allowing different classess to have methods with the same name but different underlying logic. it can be applied to the inventory system by creating a function named "subtracting_values()", before the function is called, it will ask for the category where it will remove or subtract an item from (prices, quantity of items, product name, etc.) then the way the functions operates will depend on the category. for example, "subtractig_values(prices_of_food)". This lets you write flexible code that can interact with a single interface, and in this case, a function.

## Reflection
in terms of improving the sari-sari store inventory system, encapsulation is the most helpful. This is because despite it being simple in function, it has a big impact on the organization of code. If programmers did not apply encapsulation, there would be significantly more variables, it will be harder to track mistakes, and it will be more prone to human errors during the making of the code. Encapsulation helps in storing information into categories like the price and name of the products without using many other unneeded variables, thus making it the most simple yet most impactful pillar when it comes to the inventory system.
